## Objective

Make container-document extraction correct on the inputs its own format
specification allows, and make its bounds bind on the thing they claim to bound,
before ADR-0027 makes the capability a default of every published artifact. Nine
defects are in scope; each is independently observable today and each is
reproduced below with a probe result.

Scoped to fidelity and bounds. No new format, no OCR, no layout reconstruction,
no part selector, no payload-economy change.

This is corrective work, so it is a new plan rather than an amendment to M004 or
M006.

## Why the original verification did not catch these

M004's corpus was generated by a script that emitted the smallest archive that
satisfied each parser, and asserted outcome kinds, part counts, and ordering. It
never asserted extracted text equality against a reference string containing an
XML character reference, a doctype, or two attributes whose local names collide;
and it never measured peak allocation for a body whose separators are denser than
its content. The suite answered "did the right branch run" rather than "is the
text what the document says", which is exactly the gap a generated corpus leaves
open. Every work package below therefore adds the missing shape as a fixture, not
only as a unit case.

## Current implementation evidence

- `xml_tokens` (`extract.rs:1138`) unescapes `Event::Text` and `Event::CData`
  but routes every other event kind to `Ok(_) => continue`. quick-xml 0.41 emits
  a separate `Event::GeneralRef` for `&amp;`, `&lt;`, `&apos;`, `&quot;`, and
  numeric references, so those characters are dropped rather than merged.
- `Ok(Event::DocType(_))` returns `DocumentMalformed("DTD is not supported")`.
  ADR-0026 requires that no DTD is *resolved*; it does not require that the
  declaration be refused, and EPUB 2/3 XHTML commonly carries
  `<!DOCTYPE html>`.
- `parse_attributes` inserts into `HashMap<String, String>` under
  `local_name(...)`, which lowercases and discards the prefix. `r:id` and `id`
  therefore share one slot and source order decides the survivor, so the same
  archive extracts differently depending on its producer.
- `check_xlsx_sheet_sizes` fails on the declared `<dimension ref>` area before
  observing a single cell, and separately fails on `max_column * max_row`. Both
  are declaration-shaped bounds.
- `MAX_XML_TOKENS = 262_144` and `MAX_CELL_COUNT = 200_000` are independent
  literals; a row costs several tokens, so the token cap is reachable first and
  the cell cap is dead in practice.
- `parse_csv` pushes a cell on every separator with no running count; the
  `MAX_CELL_COUNT` check that exists elsewhere in the module runs only after the
  row vector is fully materialised.
- `build_result` receives a document-level `source_truncated: bool` and applies
  it to `raw_parts.last_mut()` (`extract.rs:199`). `RawPart` already carries `truncated`, and the
  XML path already knows which token was cut, so the information is discarded
  rather than unavailable.
- `FetchError::DocumentUnsupported` maps to `FetchErrorKind::ExtractError`
  (`types.rs:322`), which reaches `_ => ToolErrorCode::UpstreamFailed`. The
  code string `document_unsupported` is available at that call site and
  `fetch_tool_error` already branches on code strings for `proxy_` and
  `unsupported_content_type`.
- `src/fetch/documents/extract.rs` is 1,317 lines and 46,362 bytes against the
  ordinary-file ceiling of 1,600 lines and 80 KB; it carries no ratchet row, so
  the ordinary ceiling applies.
- The documents module has no live network path and writes nothing to disk; all
  nine defects are reachable from a body already admitted by the pre-body gate.

## Invariants that cannot regress

- Exactly nine advertised tools plus three callable aliases; no argument, wire
  string, or tool-contract change.
- Deterministic part order and one-based part addressing: DOCX body order, PPTX
  `presentation.xml` slide order, workbook sheet order, EPUB spine order, fixed
  CSV row blocks. No ordering may become hash- or directory-order dependent.
- Bounds remain enforced on real inflated bytes, never on central-directory
  sizes: 64 MiB decompressed, 100:1 ratio, 4,096 entries, 4,096 parts, XML
  depth 64. No DTD subset, external entity, `XInclude`, or external
  relationship is resolved.
- A malformed container never returns an empty success. `document_empty`,
  `document_malformed`, `document_unsupported`, `document_encrypted`, and
  `document_disabled` keep their meanings.
- Feature-off behaviour is byte-identical to `40e362f`: a container URL still
  returns `unsupported_content_type` and CSV still returns its table preview.
- Sanitisation is applied after extraction and is not bypassed by any new text
  path.
- No new dependency, no MSRV move, no `FetchErrorKind` variant.

## Failure semantics

Extraction runs after the body is admitted and is bounded by caps, never by the
fetch deadline: a wall-clock bound would make output non-deterministic, which
ADR-0026 rejects. A malformed container never returns an empty success, a
refusal always names the bound or the shape it tripped, and no work package adds
a timeout, a retry, or a fallback to reading bytes as text.

## Ordered work packages

1. **Reference and entity resolution.** Handle `Event::GeneralRef` in
   `xml_tokens`: decode the five predefined XML entities and decimal and
   hexadecimal character references into the surrounding text run, and preserve
   an undeclared named reference as its literal source text rather than dropping
   it. Solves defect 1. Do not embed an HTML entity table; a name the document
   never declared stays visible, which is honest and keeps output independent of
   a table version. Fixture: DOCX body `Q&amp;A &lt;tag&gt; caf&#233; &quot;x&quot; &apos;y&apos;`
   asserting exact extracted text, plus an EPUB spine document using `&nbsp;`
   asserting the literal survives countably.
2. **Doctype acceptance without entity expansion.** Accept a `DOCTYPE` whose
   body contains no internal subset and no external identifier; refuse a body
   containing `[`, `SYSTEM`, or `PUBLIC` (case-insensitive) exactly as today.
   Solves defect 2 while keeping ADR-0026's no-resolution contract. Fixtures: an
   EPUB whose content documents start with `<!DOCTYPE html>`; a container whose
   doctype declares an internal subset, which must still fail.
3. **Namespace-qualified attribute identity.** Key parsed attributes by
   `(prefix, local)` with the prefix preserved, and make the relationship lookup
   ask for `r:id` explicitly. Solves defect 3 and removes producer-order
   dependence. Fixture: one PPTX written with `r:id` first and one with `id`
   first, both asserting the same slide text and relationship resolution.
4. **XLSX bounds that bind on observed content.** Stop treating the declared
   `<dimension>` and the `column * row` product as content; bound on cells
   actually materialised, stopping iteration at the cap. Derive
   `MAX_XML_TOKENS` from `MAX_CELL_COUNT` with a stated per-row factor and a
   fixed overhead so the cell cap is the binding constraint and the two cannot
   drift apart again. Solves defects 4 and 5. Fixtures: a one-cell sheet
   declaring `A1:XFD1048576`, which must extract; 45,000 one-cell rows, which
   must reach the cell bound rather than the token bound; and a genuine
   over-cap sheet, which must still refuse.
5. **CSV structural bound.** Enforce the cell count incrementally during the
   scan, so the refusal happens at the cap rather than after the row is built,
   and bound the total across the document. Solves defect 6. Evidence: the peak
   allocation of a delimiter-dense fixture before and after, measured with the
   retained command form in this plan, with the admitted body size stated beside
   each figure. The target is a peak that is a multiple of the admitted body, not
   a multiple of the separator count.
6. **Truncation attribution.** Carry the truncation point out of each extractor
   into the `RawPart` it belongs to and drop the document-level inference in
   `build_result`. Solves defect 9. Fixture: a multi-part document whose first
   part reaches the character budget, asserting the first part is flagged and
   the later parts are not, with `document_truncated` still true.
7. **Capability-miss classification.** Map `document_unsupported` to
   `capability_unavailable` at the tool boundary, alongside `document_disabled`
   and `pdf_not_compiled_in`. Solves defect 8 using the existing code-string
   branch; no new `FetchErrorKind`. Test: an RTF or ODT target asserting the
   tool error code, with `document_malformed` still reporting `upstream_failed`.
   The case goes in the behavioural suite that `architecture/testing.md` assigns
   to `fetch` tool errors — `tests/mcp_tools.rs` holds the adjacent capability
   triad — not in `extract.rs` unit tests, because the mapping is a tool-boundary
   decision.
8. **Derived cache version.** Bump `renderer_version` from 5 to 6, because
   packages 1, 2, 5, and 6 change extracted text or produce content where a
   refusal was cached. Add the isolation case proving a pre-bump entry is not
   served. Note in the closure record that the bump is global — it invalidates
   every derived entry class, not only container documents — and that this is
   the mechanism ADR-0027 relies on for the CSV path when the feature default
   flips.
9. **Documentation, guard, and suite inventory.** Correct `docs/features.md`
   § Document Formats and `docs/config.md` to state ceilings versus defaults
   (defect 7), record reference and doctype behaviour in
   `architecture/fetch.md` § Container documents, and update the
   `docs/test-inventory.md` and `architecture/testing.md` suite counts for the
   cases added above.

## Acceptance and stop conditions

- Each behavioural defect (1–6, 8, 9) has a case that fails at `40e362f` and
  passes on the candidate; the two high-severity ones assert exact extracted
  text, not a substring. Defect 7 is closed by the documentation diff.
- Feature-off behaviour is unchanged: the parity run passes and
  `unsupported_content_type` still reaches a container URL.
- `renderer_version` is 6 and a pre-bump cached entry is demonstrably not
  served.
- The declared-dimension sheet extracts; the genuinely over-cap sheet still
  refuses; the 45,000-row sheet reports the cell bound.
- The delimiter-dense CSV peak is bounded by a small multiple of the admitted
  body and the figure is recorded beside the before value.
- `extract.rs` stays under 1,600 lines and 80 KB, or the concern decomposition
  lands in the same change.
- **Stop and re-plan** if the CSV bound needs a streaming rewrite of
  `parse_csv` rather than an incremental count — that is a bound-architecture
  change and belongs to its own milestone.
- **Stop and record a limitation** if accepting a plain doctype cannot be done
  without resolving an entity; keep the refusal and document it rather than
  weakening ADR-0026's no-resolution contract.
- **Stop and re-plan** if cache isolation for the version bump would require the
  derived key to carry a feature bit; that is a cache-contract change.
- **Do not** change the default feature set, the config surface, the tool
  surface, or any bound value other than the two named constants in package 4
  and the incremental count in package 5. Default enablement is M008.

## Non-goals

- Making `documents` a default feature, or any packaging, wheel, or producer
  change. ADR-0027 and M008 own that.
- A part selector, per-part payload controls, or any payload-economy change.
- ODF, RTF, legacy binary Office, or any new format.
- An HTML entity table, character-set transcoding beyond the XML declaration, or
  Unicode normalisation of extracted text.
- CSS-aware extraction, hidden-text detection, or structural anomaly reporting.
- A new `FetchErrorKind`, a new outcome code, or a new warning code.
- Rewriting the CSV parser as a streaming state machine, unless a stop condition
  above is met and a separate milestone is filed.

## Handoff notes

Start from the failing observation, not from the fix: write the fixture and the
assertion first so the case fails on the baseline, then change the parser. The
four defects that change extracted text or produce content where a refusal was
cached (packages 1, 2, 5, 6) all ride the single version bump in package 8 — do
not add a second bump, and do not split the bump from the change that needs it.
The `extract.rs` headroom is small; check the line count after each package
rather than at the end.
